# Contributing to Awaaz

Thank you for your interest in contributing to **Awaaz**! We welcome contributions to our bilingual English + Punjabi streaming speech recognition system.

---

## 1. Core Principles & Global Rules

Every contributor (human or AI agent) must strictly follow our engineering principles:

1. **Plan first, then build**: Outline changes, verify acceptance criteria, implement, verify with tests, and report real results.
2. **Never claim something works without running it**: Always run tests and paste the actual output. Never invent WER numbers or test speeds.
3. **Weak dev machine rule**: Keep the entire local test suite running under ~2 minutes on a dual-core CPU. Use tiny synthetic fixtures generated by `scripts/make_fixture.py`. No heavy local downloads or local training loops.
4. **Everything reproducible**: Fixed seeds, configs in YAML, atomic file writes for checkpoints.
5. **Honor the Sacred-Text Policy (§1.5)**:
   - Manifests carry an optional `domain` field. Clips identified as sacred/devotional are tagged `"sacred"`.
   - **v1 strictly excludes `sacred` clips from training, dev, and test sets**.
   - No automatic correction, summarization, or rewriting of sacred text anywhere in the product.
   - Any future Gurbani support must be a separate, opt-in, human-reviewed path.
6. **No unlicensed data**: Record all dataset sources, versions, and licenses in `DATA_LICENSES.md`. Never scrape copyrighted media.
7. **No secrets in the repo**: Hugging Face and cloud API tokens must come from environment variables.

## 2. Development Setup

### 2.1 Prerequisites
- Python 3.10+ (tested on Python 3.10, 3.11, 3.12)
- Git

### 2.2 Installation
```bash
# Clone the repository
git clone https://github.com/Paramveersingh-S/Awaaz.git
cd Awaaz

# Create and activate virtual environment
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# Install in editable mode with development dependencies
pip install -e .[dev,pipeline,export]
```

### 2.3 Running Tests and Linter
```bash
# Run complete test suite (must pass in < 2 minutes)
pytest -v

# Run code style and lint checks
ruff check .

# Automatically fix lint issues
ruff check --fix .
```

## 3. Pull Request Guidelines

1. **Small, Focused PRs**: Submit one logical change per PR with a descriptive commit message following Conventional Commits (e.g. `feat(model): ...`, `fix(decode): ...`).
2. **Tests are Mandatory**: Every new feature or bug fix must include corresponding unit tests under `tests/`. Do not weaken existing tests.
3. **Update Progress & Decisions**: If making architectural changes, document them in `docs/DECISIONS.md` as an Architectural Decision Record (ADR), and update `docs/PROGRESS.md`.
4. **Code Style**:
   - Follow standard Python type hints.
   - Every public function must include a docstring detailing argument types, shapes, and units (e.g. seconds vs frames vs samples).
